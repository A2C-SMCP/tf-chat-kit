# ADR-004：标准聊天模型与 raw 数据

- 状态：Accepted
- 日期：2026-07-14

## 背景

服务端 DTO、Socket.IO 载荷和 UI 展示需求的演进速度不同。直接把服务端结构暴露给 Runtime 和 UI 会让所有宿主被后端字段变化牵动；完全丢弃原始数据又会降低新事件试用和故障排查能力。

## 决策

Gateway 在边界处执行运行时校验，并将数据转换为 `@turingfocus/chat-protocol` 定义的标准模型。模型覆盖以下稳定语义：

- Conversation 与其标识、标题和时间信息。
- Timeline 中的 Message、Agent Event 和系统状态项。
- Run 的生命周期、当前状态和中断能力。
- snapshot、增量更新、错误和 capabilities。

标准项可以携带只读 `raw` 数据，保存经过安全处理的原始载荷。`raw` 用于排障、遥测和尚未标准化的扩展，不得成为内置 Runtime 逻辑或默认 UI 的主要数据来源。

未知事件必须转换为可识别的 unknown event，并由 UI fallback 展示；不得因为出现新事件类型而丢弃整个消息流或使 Runtime 崩溃。

标准模型负责提供稳定标识和顺序信息，使 Runtime 能处理历史批量加载、增量拼接、重复投递和流式更新。服务端仍是持久数据与运行结果的事实源，Runtime 只维护客户端会话状态。

## 兼容规则

- 服务端新增可选字段或未知事件时，旧客户端应继续运行。
- 标准模型新增可选能力属于向后兼容演进。
- 改变已有字段语义、标识规则或命令结果属于破坏性变化。
- 兼容矩阵记录每个 Chat Kit 版本验证过的 TFRobotServer 基线。

## 影响

- UI 和宿主依赖稳定语义，不必理解服务端 DTO。
- Gateway 映射成为关键测试边界。
- `raw` 保留了渐进接入能力，但需要认证信息和敏感字段清理规则。

## 未采用方案

- 完全使用服务端 DTO：变化会穿透全部宿主。
- 完全标准化且不保留 raw：新事件试用和现场排障成本更高。
