# Chat Kit 默认 UI 与交互提案 01

日期：2026-10-13。状态：用户已批准，按 #129 实施；尚未发布。原型入口：http://127.0.0.1:4317/ 。对照现状：http://127.0.0.1:4316/ 。

## 1. 产品目标与范围

用户在 Word 侧栏打开插件后，能够通过默认成品 UI 完成登录、选择账户/组织、选择机器人、必要的平台确认、创建与切换对话、发送与中断、重新认证。宿主不再重做这一组通用页面。

本方案采用“可选完整体验 + 保留独立组件”的交付形式。现有无样式/Headless 接入继续可用，原有 ChatWorkspace 默认值不被静默替换。

范围判定：**ADR REQUIRED + SPLIT**。登录和聊天原子组件已有公开能力；跨身份、机器人和聊天的完整页面编排，是对 ADR-010/012/013/014 与章程既有宿主页面职责的扩展。设计可以先评审，生产实现前需接受新的 ADR，明确只把通用界面与局部导航交给可选 UI；身份来源、认证持久化、服务端点、信任列表、平台预设与宿主生命周期仍由宿主控制。

不加入 Word API、Front 源码、全局客户端或任何隐式持久化。原型中的 Word 文档只是背景图形，不表示读取、选中文档或写入文档功能已存在。

## 2. 视觉系统

- 侧栏优先：容器 320–599px 为 compact，600px 以上为 comfortable。按组件容器宽度判断，而非浏览器窗口宽度。主布局始终可收敛为单列；宽屏最大阅读宽度 680px，历史仍按需打开。
- 明亮、克制、内容优先：白底、墨绿文字、低饱和绿色操作色；白标主题可通过 Ant Design tokens 覆盖。不给默认 UI 添加大型营销头图、渐变或装饰动画。
- 建议 tokens：primary #236653；text #293832；secondary #6C7973；border #E3E9E5；surface #FFFFFF；subtle #EFF5F1。辅助文字需在实现时完成对比度复核，当前原型不是 WCAG 合规证明。
- 间距基准 4px；页面边距 16–24px；控件高 40–44px；消息正文 14px/1.75（紧凑原型 13px供评审）；常规界面字号 12–14px；页面标题 22–24px；圆角输入8/卡片10/气泡12px。
- 新完整 UI 默认 zh-CN，提供完整 en-US 字典。独立旧组件的英文默认值保持兼容；禁止复用 Playground 私有语言文件作为生产依赖。
- 默认呈现“回复中、已停止、连接中”等用户语言；Diagnostics、run 状态、事件布局模式、协议字段和地址不常驻主界面。

## 3. 布局与导航

侧栏由四部分组成：顶部上下文、局部导航/标题、可滚动主体、固定输入区。页面不与聊天列表双重滚动；软键盘、缩放与短高度下输入区仍可达。

聊天顶部第一行：当前组织入口 + 账号头像。第二行：机器人名称与切换入口，下方小字显示当前平台；第三行：当前会话标题 + 历史、新建、更多。可访问名称与 tooltip 必须补齐。

compact 历史、账号、机器人选择打开为覆盖主体的全宽子页，有明确返回按钮；退出时恢复触发按钮焦点。禁止固定 280px 会话栏挤占 320–480px 容器。确认框限制在当前组件容器内，portal 必须可由宿主配置，避免逃逸到整个 Word 页面。

## 4. 首次接入流程

1. **恢复中**：若宿主提供有效认证恢复，显示短暂骨架/“正在恢复登录”；不闪现密码页，不主动读取浏览器全局存储。
2. **登录**：账号、密码、显示密码、登录。加载时禁用重复提交；错误在表单内说明，保留账号，提交结束清空密码。忘记密码/注册只在宿主提供真实动作时展示。环境由宿主固定，只有非生产才显示“测试环境”提示，不给普通用户输入服务地址。
3. **账户/组织**：展示服务端返回的账户选项与组织标签。模型为 AccountOption，不能将组织ID与accountId互换；同组织多身份应显示足够区分的信息。两项以上先选择卡片，再点“进入组织”；唯一一项也明确显示并确认，除非宿主已有经过验证的选择。已认证且组织已确定时跳过。
4. **机器人**：名称、可用状态与可信描述（字段缺失不编造）。可搜索，超出一页按 API 分页显示“加载更多”。不可用项保留理由，不允许连接。空列表与加载失败分别展示，不能把失败当“无机器人”。
5. **平台**：已有宿主注入且经当前机器人验证的平台则跳过；没有预设时必须明确选择并确认，哪怕只有一个选项。不硬编码 platformId，不默认选第一项，不自动创建平台。原型名称“Word 协作/通用问答”仅为模拟数据。
6. **连接中**：展示当前选择和“正在连接助手”，允许返回；超时可重试或重新选择。401引导重新认证，403提示权限，无效部署信息提示联系管理员，不提供任意改地址界面。
7. **开始聊天**：优先展示当前有效 scope 的最近会话（仅按已批准恢复策略），没有会话时显示欢迎态。选择/连接不自动创建空会话；首次发送创建会话，发送动作必须避免重复创建和重复提交。新建对话进入草稿欢迎态，首条消息前不产生远端空记录。

## 5. 日常聊天

- 用户消息用淡色气泡；助手回复以正文呈现，支持 Markdown、代码、列表与已有事件渲染器。工具事件默认折叠摘要，详情通过受控动作打开；未知事件有安全 fallback。
- 输入默认 Enter 换行、Ctrl/Cmd+Enter 发送，与现有行为保持一致；IME composition 不触发发送。按钮可见且有禁用解释。附件/文档引用/插入 Word 只有存在真实宿主能力时显示，不放无效图标。
- 回复中发送键变为“停止”，显示轻量生成状态。停止请求期间显示“正在停止”；只有收到确认才显示已停止，不把请求发出当成功。停止失败保留已生成内容并允许重试。
- 发送失败保留原消息与草稿关联。明确“未送达”可手动重试；投递结果未知时先核对服务端，不能盲目重发。重试范围不包括重新登录后自动重放消息。
- 用户滚动查看旧消息时，不强制滚到底部；新消息显示“有新回复”入口。低干扰状态用 aria-live，不逐 token 朗读。
- 新建、切换会话时按 conversation scope 保存草稿到当前实例内存。关闭浏览器/窗格后能否恢复由宿主持久化策略决定，不做“永不丢失”承诺。
- 历史面板支持分页、进入、重命名、删除；删除二次确认，失败留在当前列表，不乐观宣称成功。删除当前会话后进入欢迎态；仅删除目标会话，绝不清理其他历史。

## 6. 切换与身份边界

- 组织/用户变化：确认后立即遮蔽旧消息、清空旧草稿和机器人选择、撤销在途读取、释放旧实例；新身份通过校验后才显示对应目录。不得短暂闪现上一组织消息。
- 机器人/平台变化：提示离开当前工作范围；旧会话保留在原服务器，当前草稿按安全策略清理，不串入新 scope。平台必须重新验证。
- 有未发送内容或正在生成时，切换前提示影响；无草稿且无运行时不弹无意义确认。
- 切换会话并不等于停止服务器上的运行。确认文案明确“回复可能仍在服务端继续，返回可查看最新结果”；只有真实中断接口确认成功才能声称停止。
- 退出登录明确清理本地身份和草稿，不删除远端历史。新登录若不是原身份则不恢复旧草稿与内容。
- 普通打开设置/帮助不停止生成。返回聊天能看到持续更新。局部面板与底层实例生命周期分离。

## 7. 异常状态

| 状态 | 默认展示 | 允许动作与约束 |
|---|---|---|
| 网络断开 | 顶部温和提示，历史可读 | 保留内存草稿；暂停发送，手动重试；不无限轮询 |
| 正在恢复 | “正在恢复连接” + 必要骨架 | 对可信缓存可读，发送能力由 Runtime 决定 |
| 有限恢复 | “已恢复连接，部分过程信息可能不完整” | 服从当前 Runtime capability，不能伪装完整回放 |
| 登录过期 | “登录已过期，重新登录后继续” | 原 scope 内存草稿可保留；重新校验同身份再恢复；不自动发送 |
| 无权限 | 明确权限问题 | 遮蔽受限内容，联系管理员/更换机器人；不反复登录换票 |
| 无机器人 | 空状态和“切换组织” | 仅在真实目录加载成功且为空时出现 |
| 无平台 | “暂无可用对话平台” | 联系管理员/返回；不创建平台 |
| 会话加载失败 | 内联错误与重试 | 保留列表与上一个可信展示，但不允许向未加载目标发送 |
| 发送失败 | 失败消息行内提示 | 明确未送达后手动重试；未知投递状态先核对 |
| 账号需开通 | 简短说明 | 仅调用宿主提供的开通/联系管理员动作 |

技术错误详情放“帮助与诊断”，仅输出经过脱敏的错误码、版本、时间、关联 ID。UI 不展示原始服务端响应、Token、Cookie 或密码。

## 8. 对现有组件的落点建议

**提议 API 名称，不是当前可用导出。** 不新建独立包。可选完整组件暂名 `ManagerChatApp`，从 `chat-kit/manager-antd` 暴露；跨认证与聊天的视觉组合放在显式可选入口，须由新 ADR 允许“组合 UI”。它只组合公共认证 hooks、Manager 目录/Controller 和叶子 UI，不在门面重写 Runtime/认证状态机。

- `chat-auth/antd`：增强 LoginPanel、AccountSelectionPanel、OrganizationSwitcher 的统一布局/文案/错误呈现。新增机器人选择属于 Manager 可选 UI，不把 Manager UI 渗入通用 ChatWorkspace。
- `chat-ui-antd`：增强 ChatWorkspace compact 导航和用户向状态，复用 ChatUiShell 已有 compact 扩展点；保留旧行为并以新 preset 启用。
- `chat-kit/manager-antd`：可选流程绑定、局部导航、组合生命周期；认证客户端与部署配置仍为宿主注入。纯 `/headless` 和旧 `/antd` 不因此初始化 auth。
- 宿主：提供 AuthClient/ManagerClient 或已认证会话、连接策略、品牌与 locale、显式平台 preset（可选）、Word 文档操作（可选）、隐藏与卸载策略。
- 核心七包按新的真实功能 Changeset 计算版本；auth 若发生实际变更独立增版，不回退到核心同号。

迁移目标：宿主从“分别挂载多个 Panel + 自己写步骤判断”切换为“挂载一个可选完整组件并提供依赖”。已有自定义 UI 消费者可完全保持原状。

## 9. 原型边界与验收

原型：完整五步、机器人过滤、欢迎态、消息发送/停止模拟、历史切换、重命名/删除确认、组织/机器人/平台切换、退出确认、错误场景选择、320/380/480/760宽度。所有消息与账户都是模拟数据，未调用 Manager/Server，也不代表登录或 Word API 已实现。

原型先验：可点击、无主区横向溢出、窄屏输入区可见、对话框键盘可退出、失败提示明确。生产验收另行要求：

1. 使用打包产物运行320/380/480/760容器与200%缩放；中文/英文、长名称、长消息、短高度。
2. 完整键盘路径、可见焦点、Escape关闭与焦点回归；触摸点击区、屏幕阅读器、颜色对比、reduced-motion。
3. 真实公开认证入口驱动登录→账户选择→机器人→平台→创建/发送/实时回复→历史→退出。
4. 真实本地 HTTP/Socket 验证401/403/错误DTO/迟到响应/切换竞态；按scope防串账号、机器人、平台和草稿。
5. test 集群与真实 Word WebView走查，分别报告；网页模拟不能替代真实Word。
6. 双实例并存、隐藏/重开/卸载、StrictMode、无全局存储与凭证泄露、Headless消费者不加载UI。

本方案按 Office 任务窗格的内容优先与局部导航原则设计，但继续使用项目既有 Ant Design 技术栈，不因为宿主是 Word 就新增 Fluent UI 包。

## 11. 本轮原型实测记录

2026-10-13，通过 Playwright 在本地独立原型页面执行（全部为模拟交互）：

- 登录→组织→机器人→平台→欢迎态通过。
- 发送/模拟回复与停止生成通过。
- 历史切换后草稿恢复通过；模拟登录过期再登录后草稿恢复通过。
- 重命名保存、删除确认、Escape关闭通过。
- 断网输入禁用与重试、403遮蔽聊天内容、无机器人空态通过。
- 320/380/480/760px容器检查：主区scrollWidth不超过clientWidth，composer底部不超出容器。
- 页面重载后无控制台错误。

尚未证明：生产API行为、真实Word/WebView、屏幕阅读器、200%缩放、所有焦点回归与颜色对比。该原型测试不等同于SDK实现或发布验收。
