# #136 作者展示与临时消息恢复

日期：2026-10-14；工作基线 `origin/develop@7ef73445b39a`；#135 的 UI 变更已通过 PR #137 合并。

## 独立验证与历史复盘

实际 Gateway/Runtime 回放确认：UID 不同得到两个用户气泡；UID 相同仅昵称变化同样两个；完全相同 creator 得到一个。已有身份逻辑来自 `0a0be315`（2026-10-10，#46/#103 后续兼容验收）；保留完整业务 DTO、作者 UID 和多个数据库事实，防止误合并是有效决策。缓存合并来自 `a0dd6315`（2026-09-10，#77），保留已加载更早历史和加载期间的通知仍是约束。

最新 Server `origin/develop@821cdf8f` 只读核对：`get_msgs_page` 首屏将数据库页与未落库内存缓存合并；数据库页与内存读取非同一事务；即使没有更早页，cursor 也可能编码本页最旧持久化 ID。非空 cursor 不能证明完整恢复，也不能证明任意临时回执已落库。缺乏稳定作者及发送关联信息时，不可仅凭相同正文/时间戳跨 UID 别名。

## 实施范围

- 同 UID 的已知 `name`/`avatar` 展示字段不进入身份签名；其余业务字段、creator 扩展、不同持久化 ID 和歧义保护保留。独立 Gateway 实例为临时 ID 加随机命名空间，防止旧缓存与新连接的临时项误碰撞。
- 可选 `Message.provenance` 区分临时项、持久化 ID 与历史/实时/缓存来源。历史作者按读取发起顺序更新；别名保留最小作者与修订信息，不受最近 256 条业务签名的淘汰影响。已知 ID 作者或业务事实修正后，签名同步更新，旧 UID／业务内容不能重新取得该 ID。
- Runtime 在历史分页、缓存、并发 handoff 和迟到 echo 中统一保留已确认作者与新内容。磁盘展示投影去除作者，来源降为 `cache`，不授予历史权威或恢复证明。
- 缓存重叠与 Timeline 合并使用会话内的已知持久化 ID，并兼容未提供 provenance 的既有 Gateway 显示 ID。跨 Gateway 实例的磁盘恢复、后续分页与实时通知沿用当前显示 ID；不同持久化事实仍独立。临时项不作为历史重叠或最旧覆盖点，不提升缓存来源。
- 完整回读和 best-effort 重连保留未关联的临时项。历史读取期间的新实时项、进行中的发送与 run 保留在主列表。只有未得到关联且没有新变化的旧临时项标记为待核对；时间先后仅用于展示分区，不用于跨 UID 身份关联。
- 重连到已知检查点后仍处理同一历史页的消息作者更新，保持事件检查点边界。读取期间内容已被实时更新时，使用可选 `authorOnly` 更新保留新内容。
- 默认 UI 主列表显示历史记录；不确定临时项进入可展开的“待核对消息”区，保留正文并解释尚未确认对应历史，不自动重发。headless snapshot 保留全部数据。该可选展示偏好提问未收到回复，按此前说明采用推荐方案，用户仍可调整。

## 验证证据

正式新增回归先 FAIL 后 PASS：昵称／头像变化、磁盘作者降级、并发三方作者回退、真实 HTTP 旧响应晚于新分页、超过 256 条后的别名作者保留、实例间临时 ID 隔离、未关联临时项与 pending send 保留、历史优先的跨 UID 迟到 echo、已知 ID 修正后旧 UID／业务事实不能关联、真实 Socket 重连检查点页的作者更新、REST 临时记录关联已知 ID 后的作者更新、跨两个实际 Gateway 的磁盘缓存恢复（仅目标项／另有稳定重叠项、非空 cursor）。作者限定更新不存在目标时不插入正文，已存在时保持原正文和时间；后续不同 display ID 的同一持久化事实沿用显示身份，不同数据库 ID 保持独立。

实际本地 HTTP/Socket.IO 覆盖非空 cursor、历史期间用户回执、历史作者更新、迟到回执、两个不同持久化 ID 的同正文消息。公开打包消费者在 Chromium 与 WebKit 的 30 项浏览器走查通过，包括跨 UID 发送→回复→切换→返回→展开待核对→继续发送；此项是受控 HTTPS Server 的 Word 宿主布局模拟，并非真实 Word/test 服务验收。最终完整检查与隔离审查结果在交付记录补充。
